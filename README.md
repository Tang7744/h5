# 一个人又不会怎样 · H5 互动游戏

这是一个无需构建工具即可运行的移动端 H5，以 393 × 852 为视觉基准。手机页面铺满浏览器可用视口，桌面宽屏使用 CSS iPhone 16 外框预览。

页面视觉素材均以 Figma 文件中按 4× PNG 导出的画面为准；`ipath-Regular.ttf` 只用于浏览器生成的明信片手绘文字，正文使用系统中文字体。

## 本地运行

在项目目录启动任意静态文件服务器，例如：

```bash
python3 -m http.server 4173
```

然后打开 `http://localhost:4173`。

桌面默认显示手机外框（包括窄窗口）；真实手机与 iPad 不显示外框。开发时可打开 `http://localhost:4173/?preview=mobile`，在桌面浏览器中检查无外框的响应式布局。这个参数只改变预览容器，不改变上传、跳转和图片生成逻辑。

不要直接双击 `index.html`，部分浏览器会限制本地文件模式下的图片与下载功能。

## 已实现

- 独立活动入口页和不可返回入口的滚动长页
- 「找 i 景 / 找 i 物」板块切换
- 自定义照片访问说明和单张图片选择
- 纯前端明信片转换、信箱掉落动画、结果预览与图片下载
- Bingo 线索弹层、照片裁切填入及完成勾选
- 全宽页面、独立的长页滚动容器、全屏遮罩与底部半层
- 安全区域、动态视口高度、横竖屏切换和桌面手机外框
- 弹窗焦点管理、Escape 关闭、减少动态效果偏好

照片处理完全在浏览器本地完成，不会上传至服务器。当前转换采用示意性的中心主体保留和横向条纹效果，没有引入照片识别模型。

## 上线检查

- 通过 HTTPS 静态站点部署整个目录，保留 `assets` 的相对路径。更新后需同步更新 HTML 的 CSS/JS 版本号，避免旧缓存。
- 网页可铺满浏览器的内容区，但不能强制隐藏 Safari、微信或 Android 浏览器自身的地址栏和系统导航栏。
- 桌面外框是观看模型，不是 iOS 系统模拟器。响应式浏览器测试不能代替真实手机和微信内置浏览器测试。
- 上线前须在真实 iOS Safari、Android Chrome、微信中验证照片选择、横竖屏、浏览器工具栏收起/展开、保存图片和安全区域。
- 分享仍按产品原要求显示占位提示；Bingo 的“换一批”和完成数量目前仍是静态展示，没有新增题库或抽奖业务。完整业务上线需另行确认这些功能。

布局尺寸与弹层覆盖的实现位于 `styles.css`；视口同步和页面状态位于 `app.js`。修改 Bingo 排版时，须同时核对图片内的透明拼图区域、完成蒙层与文字区域。
